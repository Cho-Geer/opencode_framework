# Google Agent2Agent (A2A) Protocol — Summary

**Source**: https://a2a-protocol.org/latest/specification/ and https://github.com/a2aproject/A2A  
**Version**: v1.0.0 (released 2026, under Linux Foundation)  
**Accessed**: 2026-06-16 via webfetch

---

## 1. What is A2A?

An **open protocol** enabling communication and interoperability between **independent, opaque AI agent systems**. Unlike frameworks that orchestrate agents within a single codebase, A2A enables agents built on **different frameworks, by different companies, on different servers** to collaborate.

### Core Value Proposition
- Agents discover each other's capabilities
- Negotiate interaction modalities (text, forms, media)
- Securely collaborate on long-running tasks
- **Operate without exposing internal state, memory, or tools** (opacity)

---

## 2. Key Design Principles

| Principle | Description |
|-----------|-------------|
| **Simple** | Reuse HTTP, JSON-RPC 2.0, SSE — well-understood web standards |
| **Enterprise Ready** | Auth (OAuth2, OIDC, mTLS), security, observability built-in |
| **Async First** | Designed for very long-running tasks, human-in-the-loop |
| **Modality Agnostic** | Text, files, structured data, audio/video references |
| **Opaque Execution** | Agents collaborate via declared capabilities, not shared internals |

---

## 3. Core Concepts

| Concept | Description |
|---------|-------------|
| **Agent Card** | JSON metadata document: identity, capabilities, skills, endpoint, auth requirements |
| **Task** | Fundamental unit of work; stateful with defined lifecycle (submitted→working→completed/failed/canceled) |
| **Message** | Communication turn between client and agent; has role ("user" or "agent") + Parts |
| **Part** | Smallest content unit: text, file reference, or structured JSON data |
| **Artifact** | Output generated by agent (document, image, structured data); composed of Parts |
| **Context** | Optional identifier to group related tasks and messages |

---

## 4. Protocol Architecture (3-Layer)

```
Layer 1: Canonical Data Model (Protocol Buffers)
  → Task, Message, AgentCard, Part, Artifact, Extension

Layer 2: Abstract Operations
  → SendMessage, SendStreamingMessage, GetTask, ListTasks, CancelTask, SubscribeToTask

Layer 3: Protocol Bindings
  → JSON-RPC, gRPC, HTTP+JSON/REST, Custom Bindings
```

---

## 5. Core Operations

| Operation | Description | Sync/Async |
|-----------|-------------|-----------|
| **SendMessage** | Send message, get Task or direct Message response | Sync or async |
| **SendStreamingMessage** | Real-time streaming updates during processing | SSE stream |
| **GetTask** | Retrieve current state of a task | Sync |
| **ListTasks** | List tasks with filtering and pagination | Sync |
| **CancelTask** | Cancel an in-progress task | Sync |
| **SubscribeToTask** | Subscribe to task updates via push notifications | Async webhook |

## 6. Agent Discovery (Agent Card)

```json
{
  "name": "Research Agent",
  "description": "Specializes in academic paper search and analysis",
  "url": "https://research-agent.example.com/a2a",
  "capabilities": {
    "streaming": true,
    "pushNotifications": true,
    "stateTransitionHistory": true
  },
  "skills": [
    {
      "id": "paper-search",
      "name": "Academic Paper Search",
      "description": "Search academic databases for relevant papers"
    }
  ],
  "authentication": {
    "schemes": ["oauth2"]
  }
}
```

**Discovery Mechanism**: Well-known URI `/.well-known/agent.json`

## 7. Task Lifecycle

```
submitted → working → input-required → working → completed
                  ↘ failed
                  ↘ canceled
                  ↘ rejected
```

- **input-required**: Agent needs more information from user (human-in-the-loop)
- Tasks are **stateful** and persist across messages
- Terminal states: completed, failed, canceled, rejected

---

## 8. A2A vs MCP (Complementary, Not Competitive)

| Dimension | A2A | MCP |
|-----------|-----|-----|
| **Purpose** | Agent-to-agent communication | Agent-to-tool communication |
| **Opacity** | Agents are opaque (don't share internals) | Tools are transparent (defined schemas) |
| **Discovery** | Agent Cards (capabilities) | Tool definitions (function signatures) |
| **State** | Tasks with lifecycle | Stateless tool calls |
| **Scope** | Cross-organization, cross-framework | Within a single agent's toolset |
| **Transport** | HTTP(S), gRPC | stdio, SSE |

**Key insight**: A2A and MCP are **complementary**. MCP connects an agent to its tools. A2A connects agents to other agents. An agent can use MCP internally for tools while exposing A2A externally for inter-agent communication.

## 9. Enterprise Features

- **Authentication**: OAuth2, OpenID Connect, API Key, mTLS
- **Authorization**: Per-task data access scoping
- **Push Notifications**: Webhook-based async updates
- **Multi-Tenancy**: Tenant isolation via routing identifiers
- **Versioning**: A2A-Version header for protocol negotiation
- **Extensions**: Mechanism for additional capabilities beyond core spec

## 11. Relevance to Multi-Agent Architecture Design

A2A addresses a different layer than the framework-level patterns (AutoGen, CrewAI, LangGraph, Swarm):

- **Framework patterns** (Anthropic/AutoGen/CrewAI/LangGraph/Swarm): How to orchestrate agents **within** a system
- **A2A protocol**: How to connect agents **across** systems (different frameworks, organizations)

### When A2A is Relevant
- Multi-organization collaboration (Agent at Company A talks to Agent at Company B)
- Multi-framework environments (LangGraph agent + CrewAI agent collaborate)
- Enterprise architectures with independent microservice-like agents
- Scenarios requiring agent opacity (protect IP, internal state)

### When A2A is Overkill
- Single-codebase multi-agent systems (use a framework instead)
- Tightly-coupled agent coordination (need shared state)
- Simple handoff patterns (Swarm is simpler)

---

## 12. Key Takeaways

1. **A2A is the "HTTP of agents"** — a universal protocol for agent-to-agent communication
2. **Opacity is a feature** — agents don't need to share internals to collaborate
3. **Task lifecycle with human-in-the-loop** — `input-required` state enables long-running workflows
4. **Complementary to MCP** — MCP for tools, A2A for inter-agent communication
5. **v1.0 under Linux Foundation** — production-ready, enterprise-graded, multi-language SDKs
