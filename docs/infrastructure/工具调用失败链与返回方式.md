## 一、工具调用完整链路

### 1.1 三层阻断链路（完整流程）

```
┌─ Agent 决定调用工具 ──────────────────────────────────────────────┐
│                                                                     │
│  Step 1: before-hook 链执行（14 个 handler，顺序执行）          │
│  ┌─────────────────────────────────────────────────────────────┐    │
│  │ 1. anti-bypass (FIRST) — 检查 guidance gate          │    │
│  │    → 如果 guidance gate 激活 → throw（阻断所有工具）    │    │
│  │    → 如果 cumulative failures >= hardThreshold → throw  │    │
│  │    → 如果 compliance_blocks >= complianceThreshold     │    │
│  │        → throw（框架合规阻断）                        │    │
│  │                                                      │    │
│  │ 2. phase0-enforce — initial_read 阶段工具限制      │    │
│  │ 3. codegraph — impact 分析检查                        │    │
│  │ 4. config-guard — git hook bypass 防护                │    │
│  │ 5. scope — 写入作用域验证                             │    │
│  │ 6. gate — gate armed 检查                           │    │
│  │ 7. checklist — 执行清单阶段门控                         │    │
│  │ 8. dispatch — PLAN-FIRST 路由验证                     │    │
│  │ 9. uc7ks — UC7KS 知识管线强制                       │    │
│  │ 10. tdd — TDD 强制执行                               │    │
│  │ 11. task — DISPATCH-INTEGRITY 哈希校验                 │    │
│  │ 12. git-guard — git hook bypass 阻断                    │    │
│  │ 13. question-policy — 提问工具策略                     │    │
│  │ 14. json-validate — JSON 语法验证                      │    │
│  └─────────────────────────────────────────────────────────────┘    │
│                                                                     │
│  如果任何 before-hook throw → 工具不执行 → after-hook 不触发    │
│  错误返回 Agent，由 anti-bypass 追踪                           │
│                                                                     │
│  Step 2: 工具 execute() 执行 ────────────────────────────    │
│  ┌─────────────────────────────────────────────────────────────┐    │
│  │ 工具执行（如 safe_edit, safe_shell, read, ...）       │    │
│  │ → 成功：返回 output                                  │    │
│  │ → 失败：返回 output（含错误信息）                      │    │
│  └─────────────────────────────────────────────────────────────┘    │
│                                                                     │
│  Step 3: after-hook 链执行（14 个 handler，顺序执行）       │
│  ┌─────────────────────────────────────────────────────────────┐    │
│  │ 1. scope — 更新 eslint-state.json dirty_modules        │    │
│  │ 2. format — 自动格式化（非阻断）                     │    │
│  │ 3. read-track — 追踪读事件                          │    │
│  │ 4. task — 记录任务完成                             │    │
│  │ 5. audit — 追加写审计追踪                          │    │
│  │ 6. tdd — 写后 TDD 验证                            │    │
│  │ 7. uc7ks — 追踪知识管线合规性                      │    │
│  │ 8. gate — 清理过期 gate sessions                     │    │
│  │ 9. cache — 同步 knowledge_cache_state                 │    │
│  │ 10. dispatch — 清理 dispatch 状态                     │    │
│  │ 11. anti-bypass — 检测失败 + rewardReport()          │    │
│  │ 12. codegraph — 追踪 codegraph_explore 调用          │    │
│  │ 13. db-health — 监控 DB 健康状态                     │    │
│  └─────────────────────────────────────────────────────────────┘    │
│                                                                     │
│  after-hook 的 throw 不会阻断工具（工具已执行完）              │
│  错误仅记录到日志                                             │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.2 关键设计原则

| 原则 | 说明 |
|------|------|
| **Before = 阻断** | 任何 before-hook throw → 工具不执行，Agent 收到错误 |
| **After = 副作用** | after-hook 错误不阻断工具，仅记录 |
| **anti-bypass FIRST** | before 链第一个执行，防止其他 plugin 抢占强制执行 |
| **Orphan 检测** | before-hook 执行但 after-hook 未执行 → 框架合规阻断 |

## 二、工具返回值结构标准体系

### 2.1 MCP 标准返回格式（MCP Tools）

所有 MCP 工具必须遵循 MCP 标准：

```typescript
// 成功返回
{
  content: [{ type: "text", text: "<JSON 字符串或文本>" }],
  isError: false
}

// 失败返回
{
  content: [{ type: "text", text: "<错误信息 JSON 字符串>" }],
  isError: true
}
```

- `content`: 数组，每个元素是 `TextContent` 对象
- `text`: 通常是 `JSON.stringify(result)` 后的字符串
- `isError`: 框架用来判断工具是否执行成功

**实际代码验证**（`compliance-gate.ts`）：

```typescript
// 成功：status === "armed"
return { content: [{type: "text", text: JSON.stringify(result)}], isError: false };

// 失败：status !== "armed"
return { content: [{type: "text", text: JSON.stringify(result)}], isError: true };
```

### 2.2 Custom Tool API 返回格式

使用 `@opencode-ai/plugin` 的 `tool()` helper 定义的自定义工具：

```typescript
// 成功：返回任意值（框架自动包装）
async execute(args, context) {
  return "success string";  // → 框架包装为 { output: "..." }
}

// 失败：throw Error（框架捕获后设置为 metadata.error）
async execute(args, context) {
  throw new Error("tool failed");
}
```

**框架包装后的最终格式**（传递给 after-hook 的 `output` 参数）：

```typescript
output = {
  title: string,        // 工具标题
  output: string,       // 工具 execute() 的返回值（JSON.stringify 后）
  metadata: {
    error?: string,    // 只有当工具 throw Error 时才有值
  }
}
```

### 2.3 内置工具返回值

OpenCode 内置工具（如 `read`, `Read`, `glob`, `Grep`, `Bash`, `Edit`, `Write`）：

```typescript
// 成功：直接返回文本内容
{
  output: "<文件内容或搜索结果>",
  title: "<工具名> - <目标>",
  metadata: {}
}

// 失败：metadata.error 有值
{
  output: "Error: <错误信息>",
  title: "<工具名> - <目标>",
  metadata: { error: "<错误信息>" }
}
```

## 三、失败检测逻辑

### 3.1 `detectFailure(output, tool?)` 函数

**文件**: `.opencode/service/enforcement/tool-tracker.ts` (lines 160-184)

```typescript
function detectFailure(output: any, tool?: string): { failed: boolean; error: string } {
  if (!output) return { failed: false, error: "" };

  const meta = output.metadata || {};

  // 1. metadata.error 是可靠信号 — 总是检查
  if (meta.error) return { failed: true, error: String(meta.error).slice(0, 300) };

  // 2. 对于只读工具，ONLY 检查 metadata.error
  // 不扫描 output content — 文件内容可能包含 "error", "fail" 等，导致误报
  if (tool && isReadOnlyTool(tool)) {
    return { failed: false, error: "" };
  }

  // 3. 对于非只读工具，扫描 output.output 和 output.title
  const text = typeof output.output === "string" ? output.output : "";
  const title = typeof output.title === "string" ? output.title : "";

  for (const p of ERROR_PATTERNS) {
    if (p.test(text)) return { failed: true, error: text.slice(0, 300) };
    if (p.test(title)) return { failed: true, error: `${title} | ${text.slice(0, 200)}` };
  }

  return { failed: false, error: "" };
}
```

### 3.2 `ERROR_PATTERNS` 完整列表

**文件**: `.opencode/service/enforcement/tool-tracker.ts` (lines 144-158)

```typescript
const ERROR_PATTERNS: RegExp[] = [
  /error:/i,           // "error:"（不区分大小写）
  /Error:/,              // "Error:"（首字母大写）
  /FAIL(?:ED)?\b/,     // "FAIL" 或 "FAILED"
  /\bBLOCKED\b/,        // "BLOCKED"（整词匹配）
  /internal error/i,     // "internal error"
  /timeout/i,           // "timeout"
  /EACCES/,              // "EACCES"（文件权限错误）
  /ENOENT/,              // "ENOENT"（文件不存在）
  /Cannot read propert/,  // "Cannot read propert..."（undefined 访问）
  /is not a function/,   // "is not a function"
  /TypeError:/,          // "TypeError:"
  /ReferenceError:/,     // "ReferenceError:"
  /split.*undefined/i,   // "split...undefined"（常见运行时错误）
];
```

### 3.3 `detectSoftRejection(output)` 函数

**文件**: `.opencode/plugin-handlers/after/anti-bypass.ts` (lines 17-38)

```typescript
function detectSoftRejection(output: any): { rejected: boolean; reason: string } {
  if (!output) return { rejected: false, reason: "" };

  // 1. MCP 标准错误格式
  if (output.isError === true) return { rejected: true, reason: "isError=true" };

  // 2. 解析嵌套 output（output.output 是 JSON 字符串）
  const innerText = typeof output.output === "string" ? output.output : "";
  let inner: any = null;
  try { inner = JSON.parse(innerText); } catch {}

  // 3. 检查顶层 status
  if (output.status === "rejected") return { rejected: true, reason: output.reason || "rejected" };
  if (inner?.status === "rejected") return { rejected: true, reason: inner.reason || "rejected" };

  // 4. 检查错误模式
  if (innerText.includes('"session not found"')) return { rejected: true, reason: "session not found" };
  if (inner?.error) return { rejected: true, reason: String(inner.error).slice(0, 200) };
  
  // 5. 检查 verified=false（attest 工具）
  if (inner?.verified === false && inner?.error) return { rejected: true, reason: "verified=false: " + String(inner.error).slice(0, 150) };

  return { rejected: false, reason: "" };
}
```

### 3.4 关键区分逻辑

```typescript
// after/anti-bypass.ts — 互斥关系
const { failed } = recordResult(sessionId, agent, tool, output);  // detectFailure() 先检查

if (!failed) {  // 只有 !failed 才走这里
  const softReject = detectSoftRejection(output);
  if (softReject.rejected) {
    const rejCount = recordSoftRejection(sessionId, tool, softReject.reason);
    // 如果 softRejCount >= 3 → before-hook 会阻断
  }
}
```

**流程图**：
```
工具执行完成
      ↓
recordResult() → detectFailure()
      ↓
  ┌──────────┬──────────┐
  │ failed    │ !failed   │
  │ (true)   │ (false)  │
  └──────────┼──────────┘
             ↓
     recordSoftRejection() → detectSoftRejection()
             ↓
        ┌──────────┬──────────┐
        │ rejected  │ !rejected │
        │ (true)   │ (false)  │
        └──────────┼──────────┘
```

## 四、计数器与阈值

### 4.1 四种计数器

| 计数器 | 追踪内容 | 递增条件 | 重置条件 | 阈值 |
|----------|-----------|-----------|-----------|--------|
| **consecutive_failures** | 连续工具失败（含软拒绝） | `detectFailure()` 返回 `failed=true` 或 `detectSoftRejection()` 返回 `rejected=true` | **永不重置**（除非 `clearGuidance()` 被调用或 TTL 过期） | `softThreshold=2`（注入 STOP）<br>`hardThreshold=4`（阻断） |
| **total_failures** | 会话总失败次数 | 每次 `detectFailure()` 返回 `failed=true` | 永不重置（除非 TTL 过期） | `totalLimit=15`（无条件阻断） |
| **compliance_blocks** | 框架合规阻断次数（orphan before-hooks） | `recordAttempt()` 检测到 orphan before-hook（`last_before_at > last_after_at`） | **工具执行成功后重置**（`recordResult()` 中 `compliance_blocks = 0`） | `complianceThreshold=3`（阻断） |
| **soft_rejections** | 每个工具的软拒绝次数 | `detectSoftRejection()` 返回 `rejected=true` | `clearGuidance()` 被调用时删除该 session 的所有记录 | `>= 3`（`before/anti-bypass.ts` 检查） |

### 4.2 Orphan 检测逻辑

**文件**: `.opencode/service/enforcement/tool-tracker.ts` (lines 261-276)

```typescript
// ── Orphan detection: previous before-hook fired but no after-hook ──
// This means another plugin blocked the previous tool (framework compliance block)
let complianceBlocks = row.compliance_blocks || 0;
if (row.last_before_at > row.last_after_at && row.last_before_at > 0) {
  complianceBlocks++;
  db.run(
    `UPDATE tool_enforcement SET compliance_blocks = ?, updated_at = ? WHERE session_id = ?`,
    [complianceBlocks, now, sessionId]
  );
  writeLog(SRC, "WARN", {
    event: "ORPHAN-DETECTED",
    sessionId, agent, tool,
    complianceBlocks,
    detail: `Previous tool blocked by framework compliance (orphan before-hook)`,
  });
}
```

**解释**：
- `last_before_at`：最后一次 before-hook 执行的时间戳
- `last_after_at`：最后一次 after-hook 执行的时间戳
- 如果 `last_before_at > last_after_at` → 说明 before-hook 执行了，但 after-hook 没执行（工具被其他 plugin 阻断）
- 这被计为 **框架合规阻断**（`compliance_blocks++`）

### 4.3 阈值检查与行为

| 阈值类型 | 配置键 | 默认值 | 触发行为 |
|-----------|-----------|---------|-----------|
| **softThreshold** | `enforcement.tool_tracker.soft_threshold` | 2 | 注入 STOP 指令到 Agent prompt（通过 `system/anti-bypass.ts`） |
| **hardThreshold** | `enforcement.tool_tracker.hard_threshold` | 4 | before-hook throw，阻断下一个工具调用 |
| **totalLimit** | `enforcement.tool_tracker.total_limit` | 15 | 无条件阻断 session |
| **complianceThreshold** | `enforcement.tool_tracker.compliance_threshold` | 3 | before-hook throw，阻断下一个工具调用 |

### 4.4 重置条件总结

| 计数器 | 重置条件 |
|----------|-----------|
| **consecutive_failures** | **永不重置**（除非 `clearGuidance()` 被调用，或 TTL 过期） |
| **total_failures** | **永不重置**（除非 TTL 过期） |
| **compliance_blocks** | **工具执行成功后重置**（`recordResult()` 中 `compliance_blocks = 0`） |
| **soft_rejections** | `clearGuidance()` 被调用时删除该 session 的所有记录 |

**关键发现**：
- `consecutive_failures` 和 `total_failures` **不会在工具成功执行后重置**
- 这是有意设计：**累积失败计数**贯穿整个 session 生命周期
- 只有 `clearGuidance()`（Guidance Gate 两阶段协议）会重置计数器

## 八、完整失败类型矩阵

### 8.1 失败类型详解

| # | 失败类型 | 触发条件 | 检测函数 | 计数器 | 阈值阻断 | 示例 |
|---|-----------|-----------|-----------|---------|-----------|------|
| **A** | **硬失败（metadata.error）** | `output.metadata.error` 有值 | `detectFailure()` | `consecutive_failures`<br>`total_failures` | `>= hardThreshold(4)` | MCP 标准错误 |
| **B** | **硬失败（ERROR_PATTERNS）** | `output.output` 或 `output.title` 匹配 `ERROR_PATTERNS` | `detectFailure()` | `consecutive_failures`<br>`total_failures` | `>= hardThreshold(4)` | `"Error: session not found"` |
| **C** | **软拒绝（isError:true）** | `output.isError === true` 且无 `ERROR_PATTERNS` 关键词 | `detectSoftRejection()` | `soft_rejections` | `>= 3` | `{"isError":true,"output":"rejected"}` |
| **D** | **软拒绝（status:rejected）** | `output.status === "rejected"` 或 `inner.status === "rejected"` | `detectSoftRejection()` | `soft_rejections` | `>= 3` | `{"status":"rejected","reason":"..."}` |
| **E** | **软拒绝（verified:false）** | `inner?.verified === false` 且 `inner?.error` 有值 | `detectSoftRejection()` | `soft_rejections` | `>= 3` | `{"verified":false,"error":"..."}` |
| **F** | **框架阻断（before-hook throw）** | before-hook throw → 工具不执行 | `recordAttempt()` (orphan 检测) | `compliance_blocks` | `>= complianceThreshold(3)` | `Error: [FW-ENFORCE][PHASE-0] Tool "xxx" is BLOCKED during initial_read phase...` |
| **G** | **会话总失败上限** | `total_failures >= totalLimit` | `recordAttempt()` | `total_failures` | `>= totalLimit(15)` | 无条件阻断 session |

### 8.2 失败处理流程图

```
┌─ 工具执行完成 ──────────────────────────────────────────────────────────────────────┐
│                                                                               │
│  after/anti-bypass.ts handle()                                               │
│  ┌─────────────────────────────────────────────────────────────────────────────┐  │
│  │ const { failed, count, error } = recordResult(...);  // detectFailure()  │  │
│  │                                                                       │  │
│  │ if (failed) {                                                          │  │
│  │   → 硬失败（A 或 B）                                               │  │
│  │   → consecutive_failures++                                                │  │
│  │   → total_failures++                                                    │  │
│  │   → 检查阈值：                                                       │  │
│  │     if (consecutive >= hardThreshold) → 下次 before-hook 会阻断         │  │
│  │ } else {                                                               │  │
│  │   → 成功或软拒绝                                                      │  │
│  │   → compliance_blocks = 0（重置）                                      │  │
│  │                                                                       │  │
│  │   const softReject = detectSoftRejection(output);                        │  │
│  │   if (softReject.rejected) {                                           │  │
│  │     → 软拒绝（C 或 D 或 E）                                       │  │
│  │     → soft_rejections++（per-tool）                                    │  │
│  │     → 检查阈值：                                                       │  │
│  │       if (softRejCount >= 3) → 下次 before-hook 会阻断             │  │
│  │   }                                                                   │  │
│  │ }                                                                       │  │
│  └─────────────────────────────────────────────────────────────────────────────┘  │
│                                                                               │
└───────────────────────────────────────────────────────────────────────────────────────┘

┌─ 下一次工具调用 ──────────────────────────────────────────────────────────────────┐
│                                                                               │
│  before/anti-bypass.ts handle()                                              │
│  ┌─────────────────────────────────────────────────────────────────────────────┐  │
│  │ // 1. 检查 guidance gate                                               │  │
│  │ if (getAwaitingPhase(sessionId) === 1) {                               │  │
│  │     if (isClearGuidanceTool(tool) || isReportTool(tool)) → 允许       │  │
│  │     else → throw（阻断）                                              │  │
│  │ }                                                                       │  │
│  │                                                                       │  │
│  │ // 2. 检查 soft rejection 阈值（v32）                                │  │
│  │ const softRejCount = getSoftRejectionCount(sessionId, tool);              │  │
│  │ if (softRejCount >= 3) {                                              │  │
│  │   throw（阻断）                                                        │  │
│  │ }                                                                       │  │
│  │                                                                       │  │
│  │ // 3. 检查 cumulative failures                                         │  │
│  │ const { count, shouldBlock, reason } = recordAttempt(...);                │  │
│  │ if (shouldBlock) {                                                      │  │
│  │   → consecutive_failures >= hardThreshold                                 │  │
│  │   → OR compliance_blocks >= complianceThreshold                            │  │
│  │   → OR total_failures >= totalLimit                                     │  │
│  │   throw（阻断）                                                        │  │
│  │ }                                                                       │  │
│  └─────────────────────────────────────────────────────────────────────────────┘  │
│                                                                               │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

### 8.3 关键区别总结

| 区别点 | 硬失败（A/B） | 软拒绝（C/D/E） | 框架阻断（F） |
|---------|-------------------|-------------------|-------------------|
| **检测函数** | `detectFailure()` | `detectSoftRejection()` | `recordAttempt()` (orphan 检测) |
| **计数器** | `consecutive_failures`<br>`total_failures` | `soft_rejections` (per-tool) | `compliance_blocks` |
| **重置条件** | **永不重置**（除非 `clearGuidance()`） | `clearGuidance()` 删除记录 | **工具成功执行后重置** |
| **阈值** | `hardThreshold=4`<br>`totalLimit=15` | `>= 3` (per-tool) | `complianceThreshold=3` |
| **工具是否执行** | 是（工具执行了但返回错误） | 是（工具执行了但返回拒绝） | **否**（before-hook throw） |
| **是否触发 after-hook** | 是 | 是 | **否** |
