H
Four-Layer Enforcement System (Defense in Depth)
Layer 1: Git Hooks Fail-Closed
Blocks invalid commits before they enter version history
pre-commit: contract hash verify pre-commit: machine.json schema pre-commit: gate-state integrity pre-commit: rule registry digest pre-commit: DAG coverage check commit-msg: [Red/Green] {task_id}
Layer 2: framework-enforcer Plugin 14 Hooks
Runtime interception via OpenCode SDK plugin API (tool.execute, file.edited, session.lifecycle, shell.env)
tool.execute.before: DAG gate tool.execute.before: write scope tool.execute.before: TDD order tool.execute.before: contract hash tool.execute.after: file verify file.edited: real-time monitor session.lifecycle: init/compact/idle shell.env: command intercept
Known Issue: Plugin exports object not function — P0 fix pending (FW-CRASH)
Layer 3: MCP Tools 4 Programmable Gates
Programmatic compliance and quality enforcement via @modelcontextprotocol/sdk v1.29.0
compliance-gate.js: check/confirm/complete state machine code-quality-gate.js: ESLint + TS + dependency-cruiser + Prettier keystone-validate.js: SHA-256 hash verification eslint-audit.js: mock audit simulation
Layer 4: Operations Scripts ~15 Scripts
Framework maintenance, self-healing, diagnostics, and dispatch
dispatch-subagent.js pre-execution-gate.js framework-doctor.js state-reconciliation.js state-transaction.js state-integrity-scan.js framework-self-test.js gate-lifecycle-audit.js install-hooks.js rule-registry-verify.js enforcement-mode-check.sh
C
Compliance Gate State Machine
1. created — Gate session initialized with task_description + plan_summary
↓
2. armed — Preflight checks passed; agent may now execute
↓
3. confirmed — Agent acknowledges gate conditions (timestamp recorded)
↓
4. consumed — Task execution complete; gate is "used up"
↓
5. completed — Final audit appended with execution_summary
F
Self-Healing Mechanisms
Backfill Audit
Tasks completed without gate → retroactive violation records via state-reconciliation --backfill-audit
Waiver System
Approved exceptions tracked (not ignored) with responsible party, justification, repayment date (WV-2026-001 through WV-2026-012)
Scope Violation Resolution
Every role violation (7 recorded, all BLOCKER) includes resolution path with agent identity and fix task ID
Digest History
Rule changes versioned with SemVer + SHA-256 digest_history[], rollback always possible

Six-Layer Parameterization Flow
1
project.config.json — Root Configuration
Project name, path mappings (backend_src, frontend_src, contracts, state), tech stack versions, execution mode (strict/advisory), context7 query fields. Validated by project.config.schema.json.
2
DAG Generation Standard — Template Variables
{BACKEND_MODULES_COUNT}=11, {FRONTEND_COMPONENT_FAMILIES_COUNT}=4, {SECURITY_ITEMS_COUNT}=4, {DEVOPS_ITEMS_COUNT}=4 → min_tasks = 11×3 + 4×2 + 4 + 4 = 49 (actual: 246)
3
Agent Configuration — Permission Matrix
opencode.json permission.edit glob patterns: per-agent allowed/denied path arrays. Least-privilege principle applied to all 8 agents.
4
Enforcement Hooks — Runtime Interception
framework-enforcer 14 hooks: DAG gate, write scope, TDD order, contract hash, file creation, shell commands, session lifecycle.
5
MCP Tools — Programmable Gates
compliance-gate (state machine), code-quality-gate (ESLint/TS/Dep/Prettier), keystone-validate (SHA-256 hash), eslint-audit (mock scan)
6
State Machine — Runtime Feedback Loop
machine.json + gate-state.json form closed-loop: quality results feed back, violations recorded, keystone hashes verified, WAL logged.
