### **补充说明**

1. **页面交互模式**  
   - **认证相关页面**（登录/注册/忘记密码）均为独立完整的单页，含表单验证与验证码倒计时逻辑，通过 guestGuard 拦截已登录用户。
   - **CUSTOMER 预约创建流程**被设计为四步向导式体验（`/booking` → `/booking/slots` → `/booking/confirmation` → `/booking/success`），数据文档和接口规范中提到了"前端随机散列（preferredSequence）"、"乐观UI更新"等高并发优化手段，前端很可能使用 NgRx Signals 进行状态流转，含 canDeactivateBookingGuard 防误退出。
   - **Admin 页面**均采用常规的数据管理列表 + 表单弹窗/侧边栏模式，PrimeNG 组件库提供 Table、Dialog、Chart 等开箱即用控件。仪表盘为暗色数据仪表盘（Dark-First Data Dashboard）风格，基于 `#0c1220` / `#162032` / `#2ecc71` 色系（主强调色为绿色）。

2. **与路由架构的映射**  
   Angular 项目采用惰性加载的特性模块（Feature Module），对应路由规划：
   - `auth` 模块 → `/auth/login`、`/auth/register`、`/auth/forgot-password`
   - `legal` 模块 → `/legal/terms`、`/legal/privacy`（公开路由，不含认证守卫）
   - `booking` 模块 → `/booking`、`/booking/slots`、`/booking/confirmation`、`/booking/success`
   - `my-bookings` 模块 → `/my-bookings`
   - `profile` 模块 → `/profile`
    - `admin` 模块 → `/admin` 下挂载 7 个子页面（dashboard、users、services、appointments、analytics、history、settings）
   - `**` 通配符 → 404 页面（全局，位于布局之外）

3. **实时通知与 WebSocket**  
   虽然未单独列为"页面"，但系统通过全局 WebSocket 连接在导航栏或消息中心推送预约状态更新、时间槽容量变化等实时通知，影响多个页面的数据刷新（如预约列表、管理员仪表盘）。仪表盘通知铃铛（SYS-002）和消息信封（MSG-004）依赖 WebSocket 推送未读计数。

4. **文档一致性**  
   以上页面划分与 `contract.yaml`（v1.7.2）中定义的 API 端点、`SAD` 中的模块组织、`接口设计规范` 中的角色权限，以及 `admin-ui-spec.md`（v2.3.0）页面清单完全对齐，确保前后端契约清晰。

总结：该项目包含 **18 个明确的核心页面**（其中 4 个为未来阶段规划：忘记密码页、数据分析 P1、操作历史 P2、系统设置 P1），覆盖了从访客注册、客户预约到管理员后台管理的全链路功能。
