## 1. 安全架构概述

### 1.1 安全设计原则

* **最小权限原则**: 用户和系统组件仅授予完成其任务所需的最小权限
* **纵深防御**: 多层安全控制，单一防护失效不影响整体安全
* **默认安全**: 默认配置即为安全配置
* **零信任架构**: 不信任任何内部或外部请求，始终验证
* **安全左移**: 在开发早期阶段考虑和实施安全措施

### 2.1 认证机制 (Authentication)

#### 2.1.1 JWT 令牌设计

**令牌结构**:
```typescript
// Access Token 结构 (JWT Payload)
// [M-2 修改说明 v2.2.0] 移除 email 字段。
// JWT 仅签名（HMAC-SHA256）非加密，Payload 为 Base64 编码，任何持有令牌方均可解码读取。
// 依据：NIST SP 800-63B § 6.2 最小化原则；GDPR Art.5(1)(c) 数据最小化原则。
// 业务层如需邮箱，通过 sub（userId）查询数据库获取，禁止在令牌中携带 PII。
interface AccessTokenPayload {
  sub: string;           // 用户ID (subject)
  roles: string[];       // 用户角色数组
  permissions: string[]; // 细粒度权限
  iat: number;           // 签发时间 (issued at)
  exp: number;           // 过期时间 (expiration)
  jti: string;           // 令牌唯一标识 (JWT ID)
}

// Refresh Token 结构
interface RefreshTokenPayload {
  sub: string;          // 用户ID
  tokenFamily: string;  // 令牌家族 (防重放攻击)
  iat: number;
  exp: number;          // 较长时间 (7-30天)
}
```

#### 2.1.3 认证实现

**NestJS 认证守卫**:
```typescript
// auth.guard.ts
import { Injectable, CanActivate, ExecutionContext, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import { Request } from 'express';

@Injectable()
export class AuthGuard implements CanActivate {
  constructor(private jwtService: JwtService) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest();
    const token = this.extractTokenFromHeader(request);
    
    if (!token) {
      throw new UnauthorizedException('未提供认证令牌');
    }
    
    try {
      const payload = await this.jwtService.verifyAsync(token, {
        secret: process.env.JWT_ACCESS_SECRET,
      });
      
      // 检查令牌是否在黑名单中
      const isBlacklisted = await this.redisService.get(`token:blacklist:${payload.jti}`);
      if (isBlacklisted) {
        throw new UnauthorizedException('令牌已失效');
      }
      
      // 将用户信息附加到请求对象
      request['user'] = payload;
      return true;
    } catch {
      throw new UnauthorizedException('无效的认证令牌');
    }
  }

  private extractTokenFromHeader(request: Request): string | undefined {
    const [type, token] = request.headers.authorization?.split(' ') ?? [];
    return type === 'Bearer' ? token : undefined;
  }
}
```

**Angular 认证拦截器**:
```typescript
// auth.interceptor.ts
import { Injectable } from '@angular/core';
import { HttpInterceptor, HttpRequest, HttpHandler, HttpEvent, HttpErrorResponse } from '@angular/common/http';
import { Observable, throwError, BehaviorSubject } from 'rxjs';
import { catchError, filter, take, switchMap } from 'rxjs/operators';
import { AuthService } from './auth.service';

@Injectable()
export class AuthInterceptor implements HttpInterceptor {
  private isRefreshing = false;
  private refreshTokenSubject: BehaviorSubject<any> = new BehaviorSubject<any>(null);

  constructor(private authService: AuthService) {}

  intercept(req: HttpRequest<any>, next: HttpHandler): Observable<HttpEvent<any>> {
    // 添加认证头
    const authReq = this.addAuthenticationToken(req);
    
    return next.handle(authReq).pipe(
      catchError((error) => {
        if (error instanceof HttpErrorResponse && error.status === 401) {
          return this.handle401Error(authReq, next);
        }
        return throwError(() => error);
      }),
    );
  }

  private addAuthenticationToken(request: HttpRequest<any>): HttpRequest<any> {
    const token = this.authService.getAccessToken();
    
    if (!token || this.authService.isTokenExpired(token)) {
      return request;
    }
    
    return request.clone({
      setHeaders: {
        Authorization: `Bearer ${token}`,
      },
    });
  }

  private handle401Error(request: HttpRequest<any>, next: HttpHandler): Observable<HttpEvent<any>> {
    if (!this.isRefreshing) {
      this.isRefreshing = true;
      this.refreshTokenSubject.next(null);

      return this.authService.refreshToken().pipe(
        switchMap((token) => {
          this.isRefreshing = false;
          this.refreshTokenSubject.next(token.accessToken);
          return next.handle(this.addAuthenticationToken(request));
        }),
        catchError((err) => {
          this.isRefreshing = false;
          this.authService.logout();
          return throwError(() => err);
        }),
      );
    } else {
      return this.refreshTokenSubject.pipe(
        filter((token) => token != null),
        take(1),
        switchMap((token) => {
          return next.handle(this.addAuthenticationToken(request));
        }),
      );
    }
  }
}
```

#### 2.2.2 NestJS 授权守卫

```typescript
// roles.guard.ts - 角色守卫
import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { SystemRole } from '../enums/system-role.enum';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<SystemRole[]>('roles', [
      context.getHandler(),
      context.getClass(),
    ]);
    
    if (!requiredRoles) {
      return true;
    }
    
    const { user } = context.switchToHttp().getRequest();
    return requiredRoles.some((role) => user.roles?.includes(role));
  }
}

// permissions.guard.ts - 权限守卫
@Injectable()
export class PermissionsGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredPermissions = this.reflector.getAllAndOverride<Permission[]>('permissions', [
      context.getHandler(),
      context.getClass(),
    ]);
    
    if (!requiredPermissions) {
      return true;
    }
    
    const { user } = context.switchToHttp().getRequest();
    const userPermissions = this.getUserPermissions(user.roles);
    
    return requiredPermissions.every((permission) => 
      userPermissions.includes(permission)
    );
  }

  private getUserPermissions(roles: SystemRole[]): Permission[] {
    return roles.flatMap((role) => ROLE_PERMISSIONS[role] || []);
  }
}
```

### 2.3 会话安全

#### 2.3.1 JWT 令牌安全

**令牌安全策略**:
```typescript
// token-security.service.ts
@Injectable()
export class TokenSecurityService {
  constructor(private redisService: RedisService) {}
  
  // 1. 令牌黑名单管理
  async addToBlacklist(tokenId: string, expiresIn: number): Promise<void> {
    await this.redisService.setex(
      `token:blacklist:${tokenId}`,
      expiresIn,
      'revoked',
    );
  }
  
  // 2. 令牌家族管理（防重放攻击）
  async validateTokenFamily(userId: string, tokenFamily: string): Promise<boolean> {
    const currentFamily = await this.redisService.get(`user:${userId}:token-family`);
    return currentFamily === tokenFamily;
  }

  async rotateTokenFamily(userId: string): Promise<string> {
    const newFamily = crypto.randomBytes(32).toString('hex');
    await this.redisService.setex(
      `user:${userId}:token-family`,
      60 * 60 * 24 * 30, // 30天
      newFamily,
    );
    return newFamily;
  }
  
  // 3. 并发会话控制
  async checkConcurrentSessions(userId: string, maxSessions: number = 5): Promise<boolean> {
    const sessionCount = await this.redisService.scard(`user:${userId}:sessions`);
    return sessionCount < maxSessions;
  }

  async addSession(userId: string, sessionId: string): Promise<void> {
    await this.redisService.sadd(`user:${userId}:sessions`, sessionId);
    await this.redisService.expire(`user:${userId}:sessions`, 60 * 60 * 24 * 7); // 7天
  }

  async removeSession(userId: string, sessionId: string): Promise<void> {
    await this.redisService.srem(`user:${userId}:sessions`, sessionId);
  }
}
```

#### 2.3.2 登录安全增强

**多因素认证 (MFA)**:
```typescript
// mfa.service.ts
@Injectable()
export class MfaService {
  constructor(
    private redisService: RedisService,
    private emailService: EmailService,
    private smsService: SmsService,
  ) {}

  async requireMfa(userId: string, context: LoginContext): Promise<boolean> {
    // 风险评估规则
    const riskFactors = await this.calculateRiskFactors(userId, context);

    // 高风险场景要求MFA
    return riskFactors.includes('NEW_DEVICE') ||
           riskFactors.includes('UNUSUAL_LOCATION') ||
           riskFactors.includes('SENSITIVE_OPERATION');
  }

  async sendMfaCode(userId: string, method: 'EMAIL' | 'SMS'): Promise<string> {
    const code = this.generateRandomCode(6); // 6位数字验证码
    const ttl = 300; // 5分钟有效

    await this.redisService.setex(
      `mfa:${userId}:${method}`,
      ttl,
      JSON.stringify({ code, attempts: 0 }),
    );

    if (method === 'EMAIL') {
      await this.emailService.sendMfaCode(userId, code);
    } else {
      await this.smsService.sendMfaCode(userId, code);
    }

    return code;
  }

  async verifyMfaCode(userId: string, method: 'EMAIL' | 'SMS', code: string): Promise<boolean> {
    const key = `mfa:${userId}:${method}`;
    const data = await this.redisService.get(key);

    if (!data) {
      return false;
    }

    const { code: storedCode, attempts } = JSON.parse(data);

    // 检查尝试次数
    if (attempts >= 3) {
      await this.redisService.del(key);
      throw new BadRequestException('验证码尝试次数超限');
    }

    // 验证码匹配
    if (storedCode === code) {
      await this.redisService.del(key);
      return true;
    }

    // 记录失败尝试
    await this.redisService.setex(
      key,
      300,
      JSON.stringify({ code: storedCode, attempts: attempts + 1 }),
    );

    return false;
  }
}
```

#### 2.3.3 邮箱验证码存储安全策略

邮箱验证码采用 Redis 缓存存储，支持注册、登录和密码重置三种场景，提供企业级的安全防护。

##### 验证码存储安全设计
```typescript
// email-verification.service.ts
@Injectable()
export class EmailVerificationService {
  constructor(
    private redisService: RedisService,
    private emailService: EmailService,
  ) {}

  // 验证码类型枚举
  enum VerificationCodeType {
    REGISTER = 'REGISTER',  // 注册验证码
    LOGIN = 'LOGIN',        // 登录验证码
    RESET = 'RESET',       // 密码重置验证码
  }

  /**
   * 发送邮箱验证码
   * Redis存储格式: verification:email:{email}:{type}
   * TTL: 300秒 (5分钟)
   */
  async sendCode(email: string, type: VerificationCodeType): Promise<void> {
    // 1. 生成6位数字验证码
    const code = this.generateSecureCode();

    // 2. Redis键格式: verification:email:{email}:{type}
    const key = `verification:email:${email}:${type}`;

    // 3. 存储验证码到Redis，TTL 5分钟
    await this.redisService.setex(key, 300, code);

    // 4. 发送邮件
    await this.emailService.sendVerificationCode(email, code, type);
  }

  /**
   * 验证邮箱验证码
   * 验证成功后自动删除Redis中的验证码
   */
  async verifyCode(
    email: string,
    code: string,
    type: VerificationCodeType,
  ): Promise<boolean> {
    const key = `verification:email:${email}:${type}`;

    // 1. 获取存储的验证码
    const storedCode = await this.redisService.get(key);

    // 2. 验证码不存在或已过期
    if (!storedCode) {
      throw new BadRequestException('验证码已过期，请重新发送');
    }

    // 3. 验证码不匹配
    if (storedCode !== code) {
      throw new BadRequestException('验证码错误');
    }

    // 4. 验证成功后删除验证码（一次性使用）
    await this.redisService.del(key);

    return true;
  }

  private generateSecureCode(): string {
    // 生成6位随机数字验证码
    return Math.floor(100000 + Math.random() * 900000).toString();
  }
}
```

##### 验证码安全防护策略
| 防护措施 | 实现方式 | 安全目标 |
|---------|---------|---------|
| **Redis缓存存储** | TTL 300秒自动过期 | 防止验证码长期有效 |
| **一次性使用** | 验证成功后立即删除 | 防止重放攻击 |
| **类型隔离** | 不同业务类型独立存储 | 防止类型混淆攻击 |
| **频率限制** | 5次/分钟/邮箱 | 防止暴力枚举 |
| **邮箱格式验证** | class-validator @IsEmail() | 防止注入攻击 |

```
   ↓
```

### 3.4 CSRF 防护

**Angular + NestJS CSRF 防护**:
```typescript
// Angular CSRF服务
@Injectable({ providedIn: 'root' })
export class CsrfService {
  private csrfToken = signal<string | null>(null);
  
  constructor(private http: HttpClient) {
    this.fetchCsrfToken();
  }
  
  private fetchCsrfToken(): void {
    // 从服务器获取CSRF令牌
    this.http.get('/csrf-token', { withCredentials: true })
      .subscribe((response: any) => {
        this.csrfToken.set(response.token);
      });
  }
  
  getToken(): string | null {
    return this.csrfToken();
  }
  
  // CSRF拦截器
  intercept(req: HttpRequest<any>, next: HttpHandler): Observable<HttpEvent<any>> {
    const token = this.getToken();
    
    if (token && this.requiresCsrfProtection(req)) {
      const cloned = req.clone({
        headers: req.headers.set('X-CSRF-Token', token),
      });
      return next.handle(cloned);
    }
    
    return next.handle(req);
  }
  
  private requiresCsrfProtection(req: HttpRequest<any>): boolean {
    // 仅对改变状态的请求需要CSRF防护
    const unsafeMethods = ['POST', 'PUT', 'DELETE', 'PATCH'];
    return unsafeMethods.includes(req.method);
  }
}
```

**NestJS CSRF 中间件**:
```typescript
// csrf.middleware.ts
import { Injectable, NestMiddleware } from '@nestjs/common';
import { Request, Response, NextFunction } from 'express';
import * as csurf from 'csurf';

@Injectable()
export class CsrfMiddleware implements NestMiddleware {
  private csrfProtection = csurf({
    cookie: {
      httpOnly: true,
      secure: process.env.NODE_ENV === 'production',
      sameSite: 'strict',
    },
    value: (req) => {
      // 从请求头获取CSRF令牌
      return req.headers['x-csrf-token'] as string;
    },
  });
  
  use(req: Request, res: Response, next: NextFunction) {
    // 排除不需要CSRF防护的API
    if (this.shouldSkipCsrf(req)) {
      return next();
    }
    
    return this.csrfProtection(req, res, next);
  }
  
  private shouldSkipCsrf(req: Request): boolean {
    const skipPaths = [
      '/health',
      '/metrics',
      '/api-docs',
      '/auth/login',
      '/auth/refresh',
    ];
    
    return skipPaths.some(path => req.path.startsWith(path)) ||
           req.method === 'GET' ||
           req.method === 'HEAD' ||
           req.method === 'OPTIONS';
  }
}
```

```typescript
import { Injectable, Logger, OnModuleInit } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import * as fs from 'fs/promises';

@Injectable()
export class VaultConfigService implements OnModuleInit {
  private readonly logger = new Logger(VaultConfigService.name);
  private secrets: Map<string, string> = new Map();

  constructor(private configService: ConfigService) {}

  async onModuleInit() {
    // 优先级: Docker Secrets 文件 > 环境变量 > Vault (演示)
    await this.loadSecrets();
  }

  private async loadSecrets() {
    // 1. 尝试读取 Docker Secrets 挂载的文件
    const secretPaths = {
      JWT_SECRET: '/run/secrets/jwt_secret',
      DB_PASSWORD: '/run/secrets/db_password',
    };

    for (const [key, path] of Object.entries(secretPaths)) {
      try {
        const value = (await fs.readFile(path, 'utf8')).trim();
        this.secrets.set(key, value);
        this.logger.log(`Loaded secret ${key} from file`);
      } catch {
        // 回退到环境变量
        const envValue = this.configService.get(key);
        if (envValue) {
          this.secrets.set(key, envValue);
          this.logger.log(`Loaded secret ${key} from ENV`);
        }
      }
    }

    // 2. 演示：如果配置了 VAULT_ADDR，则覆盖读取
    if (process.env.VAULT_ADDR) {
      await this.loadFromVault();
    }
  }

  private async loadFromVault() {
    this.logger.warn('Simulating Vault secret fetch...');
    // 在实际项目中，这里会调用 Vault SDK
    // const vaultSecret = await vaultClient.read('secret/data/jwt');
    // this.secrets.set('JWT_SECRET', vaultSecret.data.value);
  }
```

#### 5.1.2 敏感数据分类与加密策略

| 数据类型 | 敏感级别 | 加密策略 | 存储格式 |
|----------|----------|----------|----------|
| **用户密码** | 最高 | bcrypt 哈希 + 盐值（rounds=12，OWASP 2023）| 哈希值（passwordHash）|
| **手机号** | 高 | AES-256-GCM 全字段加密 + SHA-256 哈希索引 | 三字段（phone 脱敏 / phoneHash 哈希 / phoneEncrypted 密文）|
| **身份证号** | 高 | AES-256-GCM 全字段加密 | 加密存储 |
| **邮箱地址** | 高 | AES-256-GCM 全字段加密 + SHA-256 哈希索引 | 三字段（email 脱敏 / emailHash 哈希 / emailEncrypted 密文）|

> **[M-1 修改说明 v2.2.0]** 邮箱敏感级别从「中/应用层脱敏/明文存储」升级为「高/AES-256-GCM 加密/三字段存储」。

> 符合 GDPR Art.4(1)、PIPL 第 4 条、OWASP A02:2021 Cryptographic Failures 要求。
> 设计依据：piiEncryptionStrategy.md § 3（邮箱加密级别升级决策）。

> **[M-3 修改说明 v2.2.0]** bcrypt rounds 统一为 12，符合 OWASP Password Storage Cheat Sheet (2023) 推荐值。

- PostgreSQL 部分唯一索引原子化抢占
- Redis 软限流前置拦截
- 精细化限流策略 (用户+时段1次/秒)

**财务字段审计**:
- Appointment.price、taxRate、taxIncludedAmount 为预约创建时从 Service 快照的金融字段，后续修改 Service 价格不影响已有预约
- 所有金融字段变更必须记录审计日志，追溯操作人和变更时间
- BookingGroup.totalPrice 由应用层按组内各 Appointment 的 taxIncludedAmount 加总，不直接写入

**超时预约安全（Overtime-Only 机制）**:
- 系统已移除多时段预约（Multi-Slot Booking）与 BookingGroup 模型，统一使用 overtimeMinutes 扩展预约时长
- 创建/更新预约时，应用层验证 overtime 不会与相邻时段的已有预约重叠，防止物理冲突
- 验证逻辑：计算 `effectiveEnd = appointmentDate + durationMinutes`，查询同一日期下 `startTime < effectiveEnd AND endTime > appointmentDate` 的其他有效预约，若存在则返回 409 Conflict
