# 通用项目执行规则框架 v3.0 (MCP强制强化版)

## 📖 文档概述

本框架提供了一个分层、可扩展的项目执行规则系统，**特别强化MCP工具调用的强制性和非可选性**。核心设计理念是：

- **MCP绝对强制原则**：所有技术决策必须基于MCP获取的最新信息
- **通用性原则**：基础规则适用于所有项目类型，技术栈可扩展
- **验证驱动执行**：检查清单驱动，关键项为阻塞检查
- **透明可追溯**：完整记录MCP调用和决策依据

## 🎯 核心原则 (MCP强化版)

### 0. 合规门禁绝对强制原则（新增·最高优先级）

> **所有**任务必须依序执行：`compliance_gate_check(task_description)` → 展示计划待用户确认 → `compliance_gate_confirm(plan_summary)`。合规门未武装（gate未armed），**严禁**进入任何分析、设计或编码阶段。此检查为P0级阻塞，优先级高于所有其他MCP调用。

### 1. MCP调用绝对强制原则

> **所有**技术任务必须首先调用合适的MCP工具获取最新技术指导、版本信息和最佳实践。未完成MCP信息收集**不得**开始任何设计、编码或配置工作。

### 2. 信息先行验证原则

> 所有技术决策必须有可靠依据，优先通过MCP工具获取，其次使用最新官方文档。基于过时或假设信息进行决策是严格禁止的。

### 3. 透明完整追溯原则

> 执行过程必须有完整记录，特别是MCP调用输出必须存档。决策依据必须可追溯到具体MCP工具输出或官方文档。

### 4. 质量门禁保障原则

> 每个关键步骤都有验证检查点，MCP验证的质量标准必须严格执行。宁可因MCP调用延迟进度，也不允许降低质量标准。

## 📋 通用检查清单框架 (MCP优先)

### 使用说明

1. **项目初始化**：根据项目类型和技术栈启用相应扩展
2. **MCP调用准备**：确定需要调用的MCP工具清单和参数
3. **阻塞性执行**：按照清单顺序执行，MCP调用项为**阻塞检查**
4. **状态标记记录**：完成一项标记一项，**完整记录MCP输出**
5. **状态跟踪强制**：必须使用任务管理工具（如TodoWrite）为每个MCP项创建跟踪任务，只有状态为'completed'且结果为'成功'或'已通过替代方案解决'时，才能进入下一阶段

## ⚙️ MCP实施机制设计

### 1. 动态MCP检查清单生成

```python
# 概念实现 - MCP驱动检查清单生成
def generate_mcp_checklist(project_config):
    """根据项目配置生成MCP驱动的检查清单"""
    
    checklist = load_mcp_base_template()
    
    # 添加技术栈MCP扩展
    for tech in project_config['tech_stack']:
        if tech in mcp_extensions:
            checklist.extend(load_mcp_extension(tech))
    
    # 添加项目特定MCP项
    checklist.extend(project_config['custom_mcp_items'])
    
    # 设置MCP阻塞性检查项
    for mcp_critical_item in project_config['mcp_critical_items']:
        checklist.set_blocking(mcp_critical_item, reason="MCP调用强制")
    
    return checklist
```

↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓

### MCP调用最佳实践

1. **MCP调用时机**：在技术分析开始前**立即调用**，不得延迟
2. **MCP参数准备**：准备好必要的环境变量、目录路径等参数
3. **MCP结果解析**：仔细解析返回的结构化指导，提取关键信息
4. **MCP信息应用**：将获取的MCP信息**直接应用于**技术决策
5. **MCP记录保存**：完整记录MCP调用时间、参数、输出和决策应用
6. **MCP失败处理**：MCP不可用时按流程处理，必须记录理由

## 🔄 框架使用工作流程 (MCP驱动)

### 第一步：MCP项目初始化

1. 确定项目类型和技术栈
2. 识别所需MCP工具类别和具体工具
3. 复制MCP基础检查清单模板
4. 启用相应的技术MCP扩展
5. 添加项目特定MCP检查项

### 第二步：MCP执行准备

1. 配置MCP调用所需的环境变量
2. 准备MCP工具的参数和配置
3. 确定MCP关键项的阻塞级别
4. 设置MCP报告模板和保存位置
5. 验证MCP工具可用性和权限

### 第三步：MCP执行监控

1. 按照MCP检查清单顺序执行
2. 标记每个MCP检查项的状态
3. 记录MCP调用输出和关键发现
4. 基于MCP输出进行技术决策
5. 定期生成MCP进度报告

### 第四步：MCP完成验证

1. 确认所有MCP检查项完成
2. 验证MCP关键项的质量标准
3. 生成最终MCP执行报告
4. 归档MCP项目文档和输出
5. 总结MCP经验教训和改进点

## ⚠️ MCP强制执行注意事项

### MCP调用绝对禁止行为

1. **禁止跳过MCP**：不得以任何理由跳过MCP调用步骤
2. **禁止使用过时信息**：不得基于记忆或过时文档进行决策
3. **禁止不记录MCP**：所有MCP调用必须有完整记录
4. **禁止忽视MCP警告**：MCP发现的问题必须处理或记录理由
5. **禁止在失败MCP未处理前继续任务**：任一MCP调用失败后，在完成失败处理流程（重试/替代方案）前，严禁启动任何后续技术任务（包括其他MCP调用）

### MCP质量门禁标准

1. **MCP调用完成率**：必须100%完成计划MCP调用
2. **MCP问题解决率**：MCP发现的高风险问题必须100%解决
3. **MCP决策追溯率**：所有技术决策必须100%可追溯到MCP依据
4. **MCP报告完整性**：MCP执行报告必须包含所有必要信息

### MCP例外处理流程

1. **MCP工具故障**：
   - 记录故障详情和时间戳
   - **立即暂停所有后续任务**
   - 尝试重试（最多3次），每次重试间隔≥30秒
   - 若重试失败，启动官方文档替代方案评估
   - **只有当前故障MCP项处理完成后，才能恢复任务执行**
2. **MCP信息缺失**：
   - 使用最新官方文档替代，必须记录替代理由和风险评估
   - 标记该MCP项为“已通过替代方案解决”
3. **MCP指导冲突**：多个MCP源冲突时，以最新官方MCP为准
4. **MCP执行超时**：设置超时限制（建议5分钟），超时后记录原因并进入例外处理流程
