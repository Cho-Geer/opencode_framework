# 通用项目执行规则框架 v2.0

## 📖 文档概述

本框架提供了一个分层、可扩展的项目执行规则系统，适用于各种技术栈的项目。核心设计理念是：
- **通用性原则**：基础规则适用于所有项目类型
- **技术适配性**：通过扩展支持特定技术栈的最佳实践
- **强制执行机制**：关键检查项确保合规性和质量
- **透明可追溯**：完整记录执行过程和决策依据

## 🎯 核心原则

### 1. 最新信息优先原则
> 在技术分析前必须获取该领域的最新最佳实践和官方指导

### 2. 验证驱动原则  
> 所有技术决策必须有可靠依据，包括官方文档、行业标准或专家系统

### 3. 透明可追溯原则
> 执行过程必须有完整记录，决策依据可追溯到具体信息来源

### 4. 质量保障原则
> 每个关键步骤都有验证检查点，确保输出质量

## 📋 通用检查清单框架

### 使用说明
1. **项目初始化**：根据项目类型和技术栈启用相应扩展
2. **执行检查**：按照清单顺序完成各项检查
3. **状态标记**：完成一项标记一项，关键项为阻塞检查
4. **文档记录**：保存检查清单状态作为项目文档

## ⚙️ 实施机制设计

### 1. 动态检查清单生成
```python
# 概念实现
def generate_project_checklist(project_config):
    """根据项目配置生成定制检查清单"""
    
    checklist = load_base_template()
    
    # 添加技术扩展
    for tech in project_config['tech_stack']:
        if tech in available_extensions:
            checklist.extend(load_extension(tech))
    
    # 添加项目特定项
    checklist.extend(project_config['custom_items'])
    
    # 设置阻塞性检查项
    for critical_item in project_config['critical_items']:
        checklist.set_blocking(critical_item)
    
    return checklist
```

## ⚠️ MCP强制执行注意事项 (Salesforce专项)

### MCP调用绝对禁止行为 (Salesforce项目)
1. **禁止跳过Salesforce DX MCP**：所有Salesforce技术任务必须首先调用相应MCP工具获取指导。
2. **禁止使用过时Salesforce信息**：不得基于记忆或过时文档进行Salesforce技术决策。
3. **禁止不记录MCP调用**：所有Salesforce DX MCP调用必须有完整记录。
4. **禁止忽视MCP警告**：MCP发现的Salesforce相关问题必须处理或记录理由。
5. **禁止在失败MCP未处理前继续任务**：任一Salesforce DX MCP调用失败后，在完成失败处理流程前，严禁启动任何后续技术任务。

### Salesforce MCP质量门禁标准
1. **MCP调用完成率**：必须100%完成计划Salesforce DX MCP调用。
2. **MCP问题解决率**：MCP发现的高风险问题必须100%解决。
3. **MCP决策追溯率**：所有Salesforce技术决策必须100%可追溯到MCP依据。
4. **MCP报告完整性**：Salesforce MCP执行报告必须包含所有必要信息。

### Salesforce MCP例外处理流程
1. **Salesforce DX MCP工具故障**：
   - 记录故障详情和时间戳
   - **立即暂停所有后续Salesforce相关任务**
   - 尝试重试（最多3次），每次重试间隔≥30秒
   - 若重试失败，启动Salesforce官方文档替代方案评估
   - **只有当前故障Salesforce MCP项处理完成后，才能恢复任务执行**

2. **Salesforce MCP信息缺失**：
   - 使用最新Salesforce官方文档替代，必须记录替代理由和风险评估
   - 标记该Salesforce MCP项为“已通过替代方案解决”

3. **Salesforce MCP指导冲突**：多个Salesforce MCP源冲突时，以最新官方Salesforce DX MCP为准

4. **Salesforce MCP执行超时**：设置超时限制（建议5分钟），超时后记录原因并进入例外处理流程
