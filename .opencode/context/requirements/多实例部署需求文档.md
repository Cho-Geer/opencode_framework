# 多实例部署需求文档

## 1. 背景与目标

在单台 PC 上同时运行多个独立的预约系统实例，每个实例拥有独立的数据库、缓存、后端 API 和前端开发服务器，互不干扰。

## 2. 功能需求

### 2.1 实例隔离
- 每个实例拥有独立的 PostgreSQL 数据库（不同数据库名、不同主机端口）
- 每个实例拥有独立的 Redis 缓存（不同主机端口）
- 每个实例拥有独立的后端 API 服务（不同端口）
- 每个实例拥有独立的前端 Angular 开发服务器（不同端口）
- 每个实例拥有独立的 Docker 容器名、卷名、网络名

### 2.2 一键生成与启动
- 通过脚本 `scripts/start-instance.sh <instance-id>` 生成实例配置文件
- 通过 `docker compose -f instances/<instance-id>/docker-compose.yml up -d` 启动
- 通过 `npx ng serve --port=<port> --proxyConfig=<path>` 启动前端

### 2.3 清理与停止
- 支持单个实例的停止与数据清理，不影响其他实例
- `docker compose -f instances/<instance-id>/docker-compose.yml down -v`

## 3. 端口分配方案

| 实例 | PostgreSQL | Redis | Backend API | Frontend | Socket |
|----------|------------|-------|-------------|----------|--------|
| instance-1 | 5432 | 6379 | 3000 | 4200 | 3001 |
| instance-2 | 5433 | 6380 | 3001 | 4201 | 3002 |
| instance-3 | 5434 | 6381 | 3002 | 4202 | 3003 |
| instance-N | 5431+N | 6378+N | 2999+N | 4199+N | 3000+N |

## 4. 生成的文件结构

```
instances/
├── instance-1/
│   ├── docker-compose.yml    # 独立的 Docker Compose 文件
│   ├── backend.env           # 后端环境变量
│   ├── proxy.conf.json       # 前端代理配置
│   ├── environment.ts        # 前端环境文件
│   └── environment.prod.ts
├── instance-2/
│   └── ...
└── instance-3/
    └── ...
```

## 5. 技术实现要点

- 使用 bash 脚本动态生成实例配置
- Docker Compose 文件使用唯一容器名、卷名、网络名
- 后端通过 `backend.env` 环境变量文件注入配置
- 前端通过 `--proxyConfig` 和 `--fileReplacements` 参数切换配置
- 数据库名使用 `booking_db_<instance-id>` 避免数据冲突

## 6. 使用流程

```bash
# 1. 生成实例配置
bash scripts/start-instance.sh instance-1

# 2. 启动后端基础设施
docker compose -f instances/instance-1/docker-compose.yml up -d

# 3. 启动前端开发服务器（新终端）
cd booking-frontend
npx ng serve --port=4200 --proxyConfig=../instances/instance-1/proxy.conf.json

# 4. 第二个实例（新终端）
bash scripts/start-instance.sh instance-2
docker compose -f instances/instance-2/docker-compose.yml up -d
npx ng serve --port=4201 --proxyConfig=../instances/instance-2/proxy.conf.json
```
