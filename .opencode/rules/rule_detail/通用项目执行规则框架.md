# 通用项目执行规则框架 v3.0 (MCP强制强化版)

## 文档概述

分层、可扩展的项目执行规则系统，**强化MCP工具调用强制性**。
- **MCP绝对强制**：技术决策必须基于MCP最新信息
- **通用性**：基础规则适用所有项目，技术栈可扩展
- **验证驱动**：检查清单驱动，关键项阻塞
- **透明可追溯**：完整记录MCP调用和决策

## 核心原则

### 0. 合规门禁绝对强制（P0最高优先级）
> 所有任务：`compliance_gate_check` -> 用户确认 -> `compliance_gate_confirm`。门未武装，**严禁**进入分析/设计/编码。

### 1. MCP调用绝对强制
> 所有技术任务必须先调用MCP获取最新指导。未完成MCP收集**不得**开始设计/编码/配置。

### 2. 信息先行验证
> 决策必须有可靠依据，优先MCP，其次官方文档。禁止基于过时/假设信息。

### 3. 透明完整追溯
> 完整记录，MCP输出必须存档，决策可追溯。

### 4. 质量门禁保障
> 关键步骤有验证检查点。宁可延迟，不降标准。

## 通用检查清单框架

### 使用说明
1. 根据项目类型/技术栈启用扩展
2. 确定MCP工具清单
3. MCP项为**阻塞检查**
4. 完整记录MCP输出，任务管理工具跟踪
5. MCP项completed且成功才能进入下一阶段

### 基础检查清单模板

```markdown
# 项目：[名称] | 类型：[类型] | 技术栈：[技术] | MCP策略：[工具清单]

## MCP强制检查（阻塞性）
- [ ] 环境验证：`node --version`, `npm audit`, context7文档
- [ ] 技术栈特定：框架CLI/配置验证/安全扫描
- [ ] 质量工具：`eslint`, `prettier`, `jest`, 构建验证

## 前置检查 -> MCP信息收集（阻塞） -> MCP技术分析 -> MCP验证决策 -> MCP执行记录
```

## MCP实施机制

### 执行流程
```
【P0】compliance_gate_check -> 用户确认 -> compliance_gate_confirm
  -> MCP检查清单 -> 环境MCP -> 技术栈MCP
  -> 【状态门禁】全部成功? -> 技术分析 -> 设计决策 -> 测试 -> MCP报告 -> 完成
```

### MCP报告内容
项目信息、检查清单完成情况、MCP调用记录（工具/时间/输出/应用）、决策追溯（决策/MCP依据/验证）、问题风险、下一步。

## 附录：MCP工具参考

| 类别 | 工具 | 用途 |
|------|------|------|
| 环境验证 | `node --version`, `npm audit` | 运行时/依赖 |
| 代码质量 | `eslint`, `prettier` | 规则/配置 |
| 测试 | `jest`, 覆盖率 | 测试状态 |
| 安全 | 漏洞扫描 | 安全报告 |

| React/Next | `react/next --version` | 版本/构建 |
| 数据库 | `prisma --version` | ORM/查询 |

### MCP最佳实践
1. 技术分析前**立即调用** | 2. 准备必要参数 | 3. 解析结构化指导 | 4. **直接应用**到决策 | 5. 完整记录 | 6. 不可用时按流程处理

## MCP强制注意事项

### 禁止行为
1. **禁止跳过MCP** | 2. **禁止过时信息**决策 | 3. **禁止不记录**MCP调用 | 4. **禁止忽视**MCP警告 | 5. **禁止失败未处理前继续**

### 质量门禁
1. MCP调用完成率100% | 2. 高风险问题100%解决 | 3. 决策100%可追溯 | 4. 报告完整

### 例外处理
1. **工具故障**：记录->暂停->重试(3次,>=30秒)->官方文档替代->完成后恢复
2. **信息缺失**：官方文档替代，记录理由
3. **指导冲突**：最新官方为准
4. **超时**：5分钟限制，记录进入例外
