# dag-quality

## Purpose

Validate a generated Task.DAG.json against structural quality constraints. Ensures every DAG meets completeness, granularity, traceability, and coverage requirements before execution begins.

## Validation Constraints

### Check 1: Completeness (C)
**Rule**: Every task must reference a requirement source, contract path, or tech debt ID.
**Field checked**: `requirement_source`, `contract_ref`
**Pass**: Each task has at least one of these fields with a non-empty value.
**Fail**: Task has no requirement_source and no contract_ref → orphan task.
**Example violation**: Task `T-FEATURE-X` has no requirement_source or contract_ref field.

### Check 2: Granularity (G)
**Rule**: No task targets more than 5 files (unless `estimated_effort` is `XS`).
**Field checked**: `target_files` array length, `estimated_effort`
**Pass**: `len(target_files) <= 5` OR `estimated_effort == 'XS'`.
**Warn**: Task targets 3-5 files (acceptable but verify).
**Fail**: Task targets >5 files without XS effort marker.
**Example violation**: Task `T-BIG-REFACTOR` has 12 target_files, estimated_effort='M'.

### Check 3: Traceability (T)
**Rule**: Every task's `requirement_source` references a real document or file in the project.
**Field checked**: `requirement_source`
**Pass**: The referenced file exists in the project, OR requirement_source contains a doc section reference (e.g., "§2.13.1").
**Warn**: requirement_source references a file that cannot be verified (may be external).
**Fail**: requirement_source references a file that does not exist.
**Example violation**: Task references `docs/missing-spec.md` which does not exist.

### Check 4: Coverage Gate (CV)
**Rule**: All `project.yaml → layers.{layer}.source_paths` have at least one task targeting them.
**Pass**: Every enabled layer's source_paths directory is matched by at least one task's target_files.
**Warn**: Layer exists in project.yaml but source_paths is empty (layer is declared but not active).
**Fail**: Layer is enabled with source_paths but no task targets files in that directory.
**Example violation**: `backend` layer enabled with source_paths `['src/backend/']` but zero tasks target files matching `src/backend/**`.

## Workflow

### Step 1: Load DAG
Read `Task.DAG.json` from project root. Verify it contains a `tasks` array.

### Step 2: Run Checks
Execute all 4 checks (C, G, T, CV) against the tasks array.

### Step 3: Report
Output a structured report with per-check results and an aggregated verdict.

## Output Format

```
DAG Quality Report — v2.8.0 (booking-system)
Generated by: @Meta-Planner at 2026-05-23T11:48:00.000Z
===========================================
[PASS] C — Completeness: 70/70 tasks have requirement_source or contract_ref
[WARN] G — Granularity: 3/70 tasks target >3 files (T-UI-REFACTOR: 6, T-DB-MIGRATE: 7, T-E2E-SUITE: 8)
[PASS] T — Traceability: 70/70 requirement_sources reference valid files
[PASS] CV — Coverage Gate: All 3 enabled layers have task coverage
===========================================
Result: 3 PASS, 1 WARN, 0 FAIL → PASS (with warnings)

Warnings detail:
  T-UI-REFACTOR: 6 target_files (threshold: 5). Consider splitting into page-level tasks.
  T-DB-MIGRATE: 7 target_files (threshold: 5). Consider splitting into table-level tasks.
  T-E2E-SUITE: 8 target_files (threshold: 5). Mark as estimated_effort='XS' or split.
```

## Result Classification

| Result | Condition |
|--------|-----------|
| **PASS** | All 4 checks pass (0 failures) |
| **WARN** | 0 failures, >0 warnings |
| **FAIL** | 1 or more hard failures |

## Integration

Used by:
- Plan mode — invoke after generating a DAG to validate before execution
- `guardian` agent — gate confirm checks DAG quality
- `arbiter` agent — reviews DAG quality failures and grants waivers

## Usage

/dag-quality validate           — Run all 4 validation checks
/dag-quality check completeness — Run completeness check only
/dag-quality check granularity  — Run granularity check only
/dag-quality check traceability — Run traceability check only
/dag-quality check coverage     — Run coverage gate check only
/dag-quality report             — Show last DAG quality report
